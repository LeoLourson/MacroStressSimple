# MacroStress

Стресс-тест синтетического кредитного портфеля. LLM предлагает сценарий по тексту
события и рекомендации по результатам расчёта. Пользователь подтверждает параметры
сценария до расчёта и утверждает готовый отчёт.

```text
Streamlit → FastAPI → LangGraph
                       ├─ LLM: сценарий → подтверждение
                       ├─ FastMCP: расчёт → NumPy / SciPy
                       └─ LLM → MCP: чтение результатов → рекомендации → утверждение
                 PostgreSQL: портфель, запуски и чекпоинты
```
## Разделение обязанностей

**Леон - контракты, оркестрация, математика, LLM**

- **Контракты**: Pydantic. Схемы сценариев, портфеля, результатов расчёта, отчётов. Валидация на границах UI - API - MCP - БД.
- **Оркестрация агентов**: LangGraph. Граф состояний, ветвления, чекпоинты.
- **Математическая модель**: NumPy, SciPy. Ядро стресс-теста: потери, вероятности дефолта, макрошоки. Формирование сценариев и рекомендаций.
- **LLM**: провайдерский слой. Режим `mock` по умолчанию, опционально внешняя или локальная. Промпты, вызовы модели.

**Георгий - MCP, БД, API**

- **MCP-инструменты**: FastMCP. Сервер, инструменты расчёта и чтения данных для LLM.
- **Базы данных**: PostgreSQL. Схема портфеля, запусков, чекпоинтов.
- **API**: FastAPI, Uvicorn. Эндпоинты запуска графа, статуса, выгрузки отчётов. Интеграция с MCP внутри API.

**Общая зона - интерфейс, окружение, тесты**

- **UI**: Streamlit. Формы подтверждения сценария, отображение расчётов, утверждение отчёта.
- **Тесты**: `pytest, `ruff, `scripts/rehearse.py` — проверка миграций и качества.
- `uv.lock` — фиксация зависимостей.

## Запуск в Docker

Нужен Docker с Compose; на Windows — Docker Desktop в режиме Linux containers.
Python, uv и PostgreSQL на хосте для этого способа не нужны.

Из корня проекта в PowerShell (команды для Windows):

```powershell
# Создать .env только при его отсутствии; существующий файл сохраняется.
if (!(Test-Path .env)) {
    "POSTGRES_PASSWORD=$([guid]::NewGuid().ToString('N'))" | Set-Content -Encoding ascii .env
}
$env:MSA_LLM_PROVIDER = 'mock'  # первый запуск без внешней модели
docker compose up -d --build --wait
```

В `.env` должен быть `POSTGRES_PASSWORD` (не `CHANGE_ME`). Используйте случайный
пароль из букв и цифр: он входит в URL подключения. Уже созданный локальным
запускателем пароль подходит. Локальный `MSA_DATABASE_URL` Compose заменяет
адресом контейнера `db`; существующая локальная база не переносится.

Интерфейс: **http://127.0.0.1:8501**. API: http://127.0.0.1:8091/docs.
По умолчанию выбран `mock`, ключи не требуются. Первая сборка скачивает образы
и зависимости; следующие используют кеш. После сборки режим `mock` не требует
внешних сервисов. Зависимости приложения устанавливаются из `uv.lock` без dev-группы.

Compose запускает PostgreSQL, затем один процесс API с миграциями и загрузкой
демопортфеля, затем Streamlit. Готовность зависимостей проверяется healthcheck.
MCP работает внутри API. UI и API используют общий образ и работают без root.
База не публикует порт на хост; порты приложения доступны только через loopback.
Это локальный однопользовательский стенд без аутентификации.

```powershell
docker compose ps
docker compose logs -f api
docker compose exec api python scripts/rehearse.py  # создаёт тестовый утверждённый отчёт
docker compose down                              # данные остаются в томе
docker compose up -d --wait                       # повторный запуск
```

Портфель, запуски и чекпойнты сохраняются в томе `macrostress_postgres-data`.
`docker compose down -v` **удаляет базу**, включая отчёты и чекпойнты.
Пароль в `.env` нужно сохранять: его изменение не меняет пароль уже созданной БД.
Исходники включены в образ; после их изменения повторите команду с `--build`.
`.env`, локальная `.venv` и `.data` исключены из контекста сборки.

Если локальный стенд уже занимает порты, остановите его через `./msa.ps1 down`
или задайте другие порты перед запуском Compose:

```powershell
$env:MSA_API_PORT = '8092'
$env:MSA_UI_PORT = '8502'
docker compose up -d --wait
```

Для DeepSeek задайте профиль и ключ в окружении текущего PowerShell:

```powershell
$env:MSA_LLM_PROVIDER = 'deepseek'
# Если ключ уже сохранён в окружении пользователя:
$env:DEEPSEEK_API_KEY = [Environment]::GetEnvironmentVariable('DEEPSEEK_API_KEY', 'User')
docker compose up -d --wait
```

Ключ передаётся только контейнеру API при запуске, в образ он не включается.
Параметры `MSA_LLM_*` можно передавать через окружение или `.env`; необязательные
параметры оставляйте незаданными, а не пустыми. Профиль `deepseek` отправляет
данные внешнему API, как и при обычном запуске.

Для LM Studio на хосте контейнеру нужен адрес `host.docker.internal`, поскольку
`127.0.0.1` внутри контейнера указывает на сам контейнер:

```powershell
$env:MSA_LLM_PROVIDER = 'local'
$env:MSA_LLM_BASE_URL = 'http://host.docker.internal:1234/v1'
$env:MSA_LLM_MODEL = 'имя-загруженной-модели'
$env:MSA_ON_PREM_HOSTS = 'host.docker.internal'
docker compose up -d --wait
```

Сервер модели должен принимать соединения из Docker; при необходимости включите
в LM Studio доступ по локальной сети и разрешите его в брандмауэре.
Сам сервер модели и её веса в образ проекта не входят.

Основа конфигурации: [uv в Docker](https://docs.astral.sh/uv/guides/integration/docker/)
и [порядок запуска Compose](https://docs.docker.com/compose/how-tos/startup-order/).

## Запуск на Windows

Нужны Python 3.12 и uv.

```powershell
uv sync --frozen
.\msa.ps1 up mock
```

Для обхода блокировки запуска исполняемых файлов 

```powershell
powershell -ExecutionPolicy Bypass -File .\msa.ps1 up
```

Интерфейс: **http://127.0.0.1:8501**. API: http://127.0.0.1:8091/docs.

Запуск создаёт локальный PostgreSQL, базу `msa_product`, применяет Alembic-миграцию,
загружает портфель, запускает один процесс API и Streamlit.
Существующий `.env` и прежняя база `msa` сохраняются. На Windows PostgreSQL использует
закреплённый архив pgserver; при первом запуске потребуется интернет.
Если путь проекта содержит кириллицу, файлы PostgreSQL размещаются в
`%LOCALAPPDATA%/msa-core-local`.

```powershell
.\msa.ps1 status
.\msa.ps1 logs api
.\msa.ps1 rehearse       # полный тестовый прогон с двумя тестовыми подтверждениями
.\msa.ps1 down
```

### Подключение LLM

```powershell
.\msa.ps1 down
.\msa.ps1 up deepseek    # DEEPSEEK_API_KEY уже задан в окружении пользователя
# либо
.\msa.ps1 up local       # сервер LM Studio на 127.0.0.1:1234
```

Нужна модель с поддержкой chat tool calls и JSON-ответов.
`MSA_LLM_MODEL`, `MSA_LLM_BASE_URL`, `MSA_LLM_TIMEOUT` и `MSA_LLM_MAX_TOKENS`
можно задать в окружении. Профиль DeepSeek обращается к внешнему API: ему передаются
введённый текст, определения драйверов и результаты расчёта.
Ключи не записываются в отчёты и передаются только процессу API.

В режиме `mock` сценарий фиксирован для любого события, рекомендации шаблонные.
Интерфейс помечает этот режим. Численный расчёт и MCP-вызовы выполняются во всех режимах.
При ошибке LLM запуск завершается ошибкой без переключения на заглушку.

## Как работать с интерфейсом

1. Посмотреть исходные данные трёх компаний и выбрать либо ввести событие.
2. Получить от LLM цепочку влияния и параметры треугольных распределений.
3. Проверить и при необходимости изменить минимум, моду и максимум; указать имя и подтвердить допущения.
4. Сравнить базовый расчёт с P5/P50/P95, посмотреть месячные траектории и вероятность нарушения ковенанта.
5. Прочитать рекомендации и раскрыть их основания.
6. Утвердить отчёт или отклонить его. Markdown скачивается после утверждения.

Стенд запускается на loopback для одного пользователя, без фоновой очереди.

## Что рассчитывается

Один тип - корпоративный кредит. Горизонт - двенадцать полных месяцев, начиная
со следующего месяца после даты оценки.
Годовые доходы/расходы распределяются поровну; долг постоянен;
проценты — по Actual/365. Три шока: выручка, себестоимость, прибавка к ставке.

Выход: EBITDA, проценты, ICR, вероятность хотя бы одного месячного нарушения
порога ICR. Шоки постоянны на горизонте, одинаковы для компаний; драйверы независимы.
Общая матрица Соболя воспроизводится по seed. Суммирование выполняется внутри
реализаций до расчёта портфельных квантилей. Портфельный ICR — отношение сумм,
а вероятность портфеля — вероятность нарушения хотя бы у одной компании.

PD, кредитные потери, ликвидность, налоги, облигации, лизинг, проектное финансирование,
Шепли и обратный стресс не рассчитываются, т е модель `prod-2`
не реализует полный функционал оригинальной системы.

## MCP и рекомендации

Модель получает описание только `get_calculation_results()`, привязанного к текущему
запуску. Она обязана вызвать его; приложение выполняет настоящий MCP-запрос через
FastMCP Client и возвращает ответ сообщением `role=tool`.
После этого модель возвращает резюме и рекомендации с ключами `evidence`.

Приложение проверяет, что ключи есть в расчёте, и отклоняет текст с цифрами.
Значения и все три квантили подставляются по ссылкам программно.
Эта проверка подтверждает источник показанных значений; правильность рассуждений
LLM проверяет человек перед утверждением. Трасса вызова видна в интерфейсе.

## Код и проверки

| Путь | Назначение |
|---|---|
| `src/msa/assets/` | Единственная финансовая модель и каталог полей/метрик |
| `src/msa/engine/` | Календарь, выборка сценариев, расчёт и агрегация |
| `src/msa/agents.py` | Два LLM-шага и диалог с инструментом |
| `src/msa/mcp.py` | Три MCP-инструмента, привязанные к запуску |
| `src/msa/workflow.py` | Пять этапов и две остановки для человека |
| `src/msa/api.py` | HTTP и выполнение до очередной остановки |
| `src/msa/db/`, `migrations/` | SQLAlchemy, Alembic и снимки запусков |
| `ui/app.py` | Единственная страница Streamlit |
| `demo/case.json` | Портфель, события и сценарий заглушки |

```powershell
uv run --frozen pytest
uv run --frozen ruff check .
uv run --frozen python -m compileall -q src ui scripts
```

Тесты включают расчёт с известным ответом, совместную агрегацию, валидацию,
настоящий MCP-транспорт, HTTP tool-call диалог с подменённым внешним сервером,
восстановление после ошибки/перезапуска и полный путь через формы Streamlit.
SQLite используется только как тестовый адаптер; запускатель использует PostgreSQL.
